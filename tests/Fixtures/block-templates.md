# Block template characterization

`block-templates.json` contains fixed inputs and expected complete markup, ordered field and region calls, and query arguments for the 18 PHP render templates in `blocks/`. The capture was made before editing any application file. No fixture is regenerated during a test. The input matrix includes field lookups and caller-supplied values, IDs and anchors, both image-plugin states, empty and repeated rows, editor previews, region inclusion and exclusion, counter dates and thresholds, gallery columns and crops, quote layouts, and news formats.

The fixture records current behavior rather than desired markup. For example, the gallery and stacked templates evaluate their more-link target expression without echoing it; their existing output has no target attribute. The legacy second link-list and stacked templates can retain the preceding row's link values when the next row has no URL. These outputs are pinned, not repaired here.

## Boundaries

`BlockTemplateScenario` includes fixture templates in a fresh local scope with only the listed caller variables. Additional caller controls invoke the actual module dispatcher with values whose string conversion emits output. WordPress and plugin functions are mocked. Distinct escaping markers distinguish HTML, attribute, URL, post-content and class sanitization calls; these markers are instruments, not implementations of WordPress escaping. The actual first-party `gallery_image_dimension` implementation computes image dimensions. Density 0 and 1 therefore remain equivalent; a mock receipt cannot turn that into an artificial difference. Portrait cases use the field definition's numeric `0.75` value. A separate malformed-ratio case pins the native TypeError. The image-sizer boundary exposes dimensions, crop choices and fallback sizes, which affect its WordPress queue and fallback filters. The attachment URL helper accepts its real single argument and ignores the legacy extra size argument. QueryDouble models the loop boundary, not database selection; its null `ID` matches WordPress 7.1.3's `WP_Query::__get` for a non-compatibility property. Real thumbnail lookup therefore falls back to the current post.

Counter time is fixed to 2024-03-15 12:00:00 UTC. Date formatting and relative-date parsing relay to PHP itself with the fixed base. The UTC timezone is restored after each render. Empty and malformed custom dates retain native false results. Cases exercise day, week, month, year and custom starts, inherited and overridden starts, negative and zero elapsed time, the one-second boundary, fractional rates and integer display thresholds. JavaScript is compared as emitted text, not executed in a browser.

The separate WordPress integration tests use real category storage, query selection, published/draft status, current-post thumbnail lookup, escaping, filters and shortcode parsing. A real image-source filter emits output during the otherwise unused side-image width lookup, protecting its observable WordPress filter effect. The Unit boundary also records that lookup. Gallery crop comparisons and module ID construction retain caller string-conversion effects; a CTA control uses the real first-party phone formatters while its action is hidden. Only ACF field retrieval and the news shortcode's plugin callback are test doubles. They make no claim about an installed ACF, image-resizer, news or browser engine. The iframe test checks actual host and sandbox filters, rejection and preview output with real WordPress escaping.

Strict identity compares the complete result, including types, array order and whitespace. The failure message is deliberately bounded so a mutation cannot trigger a multi-megabyte diff. Missing field values fail rather than silently returning a default. No blanket error suppression is used.

A generous 2,000-call escaping limit makes non-terminating template loops fail inside the test rather than consume unbounded memory. Normal fixtures stay far below this limit. QueryDouble separately rejects loops that read more than 100 times without advancing. These guards run after the template starts; they are not bootstrap or command failures.

Each block has a distinct test description while retaining every fixed case and assertion. Mutation test selection can therefore select the relevant block instead of running unrelated blocks for every trial change.

Fourteen gallery density literals carry only `DecrementInteger` exclusions. The actual helper scales densities greater than 1, so explicit densities 0 and 1 have the same result for every crop and column input. Each original generated change passed all 75 gallery cases with the real helper. The annotations attach to those individual density arguments; the neighboring column numerators remain active.
