# Page-builder characterization fixtures

These fixtures pin the behavior at source revision `c7a8b25de9e07fa3f42724f046441e3a8593cb1e` for UAMS-Web/uams-2020#642, “Bring the page-builder support in `lib` to full test coverage.” They are fixed inputs and expected outputs, never regenerated by the test suite.

`page-builder-registrations.json` captures the complete option, field-group, and block-registration arguments with both optional plugins present. `page-builder-registrations-without-plugins.json` captures their absence, including the news module's unavailable message and telephone text fields. Mixed plugin states change only the two fixed telephone-field keys in the chosen news snapshot, so either plugin can be tested independently. Translation mocks prefix both domain and text, so changes to either remain visible. The snapshots contain the real included ACF field definitions; the source of those definitions is covered separately by UAMS-Web/uams-2020#644.

`module-inputs.json` gives each field a distinct value. `module-dispatch.json` records the resulting template path, local variables, and wrapper markup for each dispatcher branch. The small templates in `page-builder-theme/blocks/` capture the include boundary, not the rendering implementation covered by UAMS-Web/uams-2020#645. Object values are normalized through JSON, and top-level local-variable names are sorted because PHP's symbol-table ordering is not part of the boundary. The caller's entire module input is omitted from the capture; individual assigned template inputs remain checked. Additional tests spell out empty, fallback, plugin, crop, news-format, and section-row behavior.

The isolated registration cases load source declarations afresh, including absent-ACF paths. The shared loader makes declarations available before another test can create a mock with the same name. WordPress integration checks exercise real roles, hooks, filters, and URL parsing. ACF's own internal field-registration implementation is outside this repository.

The public module dispatcher accepts untyped field values. Stringable values exercise existing PHP comparisons through that boundary, rather than treating normal UI enum values as a guarantee about all callers. ACF also documents a mixed return value for [`get_field()`](https://www.advancedcustomfields.com/resources/get_field/) and a public [`acf/format_value`](https://www.advancedcustomfields.com/resources/acf-format_value/) filter. These tests do not claim to execute an installed ACF implementation.

A false image group takes the existing empty-image fallback while emitting a PHP warning at the anchor lookup. The characterization catches only the known warning text in the actual rendering function and source file, requires exactly one occurrence, and verifies both empty image data and the center anchor. Other errors throw. Function bounds are read from reflection because the mutation tool pretty-prints source and shifts its physical lines. A formatted-but-unchanged source control still passes; a changed fallback fails its value assertion.
